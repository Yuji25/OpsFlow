# OpsFlow

OpsFlow is a cloud-native incident and service operations platform. Phase 1 converts the Session 21 TaskBoard starter into an incident application while keeping its FastAPI, SQLAlchemy, PostgreSQL, Alembic, and React architecture.

## Application

The responsive dashboard supports incident creation, editing, status selection, deletion, status filters, severity badges, and recent incidents ordered by their last update. Loading, empty, and backend-error states include retry support.

Dashboard cards count Open, Investigating, Resolved, and **unresolved Critical** incidents. Resolved incidents never contribute to the Critical count.

Incident fields: `id`, `title`, `description`, `service`, `severity`, `status`, `assignee`, `created_at`, `updated_at`.

- Required: nonblank title (up to 200 characters) and service (up to 120).
- Severity: `LOW`, `MEDIUM` (default), `HIGH`, `CRITICAL`.
- Status: `OPEN` (default), `INVESTIGATING`, `RESOLVED`.
- Description defaults to empty; assignee defaults to `Unassigned` (up to 120 characters).
- UTC creation/modification timestamps are generated by the backend. Modification time changes when details change.

## Run locally

Use a reachable PostgreSQL database and Python 3.12, matching the backend container. Install the existing requirements without changing their versions:

```bash
cd backend
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
export DATABASE_URL='postgresql+psycopg://opsflow:opsflow@localhost:5432/opsflow'
alembic upgrade head
uvicorn app.main:app --reload --port 8000
```

If Python 3.12 is unavailable, use an installed compatible interpreter and record its version. Configuration can also be placed in `backend/.env` using `.env.example`.

In another terminal:

```bash
cd frontend
npm install
npm run dev
```

Open [the dashboard](http://localhost:5173) or [API docs](http://localhost:8000/docs). Vite proxies `/api` to port 8000.

### Docker Compose

Requirements: Docker Engine and Docker Compose with healthcheck dependency support. From the repository root:

```bash
docker compose config
docker compose up --build
```

Open [the Docker-served dashboard](http://localhost:3000) and [Swagger docs](http://localhost:8000/docs). PostgreSQL is published on localhost:5432. Stop the foreground stack with Ctrl+C; `docker compose down` removes containers/network but retains the database volume. Do not use `down -v` on a project containing data you need.

PostgreSQL readiness gates backend startup. The backend runs `alembic upgrade head` before starting Uvicorn; its healthcheck calls `/ready` using Python's standard library. The frontend waits for backend readiness and serves the production Vite build through non-root Nginx on container port 8080, published as port 3000. Its healthcheck uses the image's `wget`; PostgreSQL uses `pg_isready`. The browser's `/api/incidents` requests pass through Nginx to `backend:8000`. No host Vite server or Python environment is needed. The frontend internal port is now 8080; existing Helm port settings are deliberately unchanged and must be aligned in the later Kubernetes/Helm phase.

The frontend uses exact dependency versions and a committed lockfile with `npm ci`. Backend dependency versions remain those in `requirements.txt`; no new backend lockfile is introduced. Local environment files/private-key files are excluded from service build contexts. The bundled `opsflow` database credentials are local development defaults, not production credentials.

#### Safe fresh-database validation

If another PostgreSQL container occupies port 5432, leave it and its volume alone. Use this separate project, which creates its own `opsflow-phase3-validation_postgres-data` volume and maps PostgreSQL to port 55432:

```bash
POSTGRES_PORT=55432 docker compose -p opsflow-phase3-validation config
POSTGRES_PORT=55432 docker compose -p opsflow-phase3-validation build
POSTGRES_PORT=55432 docker compose -p opsflow-phase3-validation up --build -d --wait
POSTGRES_PORT=55432 docker compose -p opsflow-phase3-validation ps
curl -fsS http://localhost:8000/health
curl -fsS http://localhost:8000/ready
curl -fsS http://localhost:8000/metrics
curl -fsS http://localhost:8000/docs
```

Ensure ports 3000, 8000, and 55432 are free and the temporary project/volume do not already contain data you need. Verify create/edit/delete in the Docker-served dashboard, then create a persistence marker and restart backend/frontend to confirm it remains. Only after confirming that this project was created solely for disposable validation, clean up **that project only**:

```bash
POSTGRES_PORT=55432 docker compose -p opsflow-phase3-validation down -v --rmi local
```

This intentionally deletes only the temporary project's containers, network, database volume, and locally named application images. Never substitute your normal project name or run Docker prune commands. Capture actual Compose status/logs and dashboard screenshots manually after review; screenshots are not generated by the application.


## API

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/` | OpsFlow service/version information |
| GET | `/health` | Liveness (`UP`) |
| GET | `/ready` | Database/table readiness (`READY`) |
| GET | `/metrics` | Prometheus request metrics |
| GET | `/api/incidents` | List incidents, newest ID first |
| GET | `/api/incidents/stats` | Counts: total, open, investigating, critical, resolved |
| GET | `/api/incidents/{id}` | Retrieve an incident |
| POST | `/api/incidents` | Create (201) |
| PUT | `/api/incidents/{id}` | Update supplied fields (200) |
| DELETE | `/api/incidents/{id}` | Delete (204, empty response) |

Missing incidents return 404. Invalid input, including explicit null incident fields, returns 422. Omitted PUT fields remain unchanged. There are no legacy task API aliases.

```bash
curl -fsS http://localhost:8000/health
curl -fsS http://localhost:8000/ready
curl -fsS http://localhost:8000/api/incidents/stats
curl -fsS -X POST http://localhost:8000/api/incidents \
  -H 'Content-Type: application/json' \
  -d '{"title":"Checkout errors","service":"checkout-api","severity":"CRITICAL"}'
```

## Database and migrations

`backend/alembic/versions/0001_create_incidents.py` creates the `incidents` table; downgrade drops that table. Run Alembic from `backend/`. The existing backend container still runs migrations before Uvicorn. The starter's startup `create_all` behavior is retained, but migrations remain the supported schema-management path.

**Fresh database required:** the starter task revision has been replaced, not migrated. An existing database stamped with `0001_create_tasks` is incompatible with this new history. Keep any old database/volume intact and provision a separate fresh database (or a separate Compose project/volume). Changing `POSTGRES_*` in Compose does not rename roles/databases inside an initialized volume. No automatic reset or task-record conversion is provided. `alembic downgrade base` deletes incident data; use only on disposable databases when validating migrations.

## Validation

```bash
cd backend
.venv/bin/python -m pytest -q
.venv/bin/python -m compileall -q app alembic tests
.venv/bin/python -c 'from app.main import app; print(app.title)'
alembic current
alembic check
```

API tests use a fresh in-memory SQLite database for each test and run application startup; they never connect to PostgreSQL. Passing these tests does not verify PostgreSQL migrations. Verify `alembic upgrade head` and schema consistency against a fresh PostgreSQL database separately.

```bash
cd frontend
npm run build
```

In the browser, create a critical incident, edit it to Investigating then Resolved, confirm the KPI changes, filter the list, and delete it. Check desktop/mobile layouts and retry behavior while the backend is unavailable.

## Deferred infrastructure

Terraform, Helm, Kubernetes, monitoring, troubleshooting manifests, and load-test helpers retain the starter architecture. Docker/Compose hardening is covered above. The `helm/taskboard` chart, Kubernetes namespace, image names, hostnames, Terraform resources, and load-test URL still use TaskBoard naming. `GRADING.md` is the original course rubric. These references are intentionally retained for a later DevOps phase.

Known starter routing issues deferred to that phase: Helm ingress names/port do not match the templated backend service (ingress uses port 8080 while the service uses 8000); Nginx targets `backend:8000`, which matches Compose but not the Helm service name; the load-test helper defaults to `/api/health` while the application exposes `/health`. The starter README mentioned CI/CD, but no `.github/workflows` directory exists in this checkout. Phase 1 does not add or repair those deployment components.

Authentication, a service catalog, pagination, alert ingestion, and infrastructure changes are outside Phase 1.
